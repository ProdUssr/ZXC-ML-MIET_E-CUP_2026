## Блок B — семантика и калибровка

`RulesPredictor` формирует независимые признаки `has_positive`, `has_negative`,
`n_positive_bucket`, категорию и узкий флаг явного логического исключения. И
позитивные, и негативные Evidence сохраняются; негатив больше не имеет
абсолютного приоритета. Широкие основы `лак\w*` и `краск\w*` заменены явными
словоформами. Поэтому «Лакомство для собак» не становится уликой лака, а
«Зажигалка со встроенным фонариком» содержит оба независимых бита и остаётся
регулируемой.

`submission/calibration.json` строится `train/fit_calibration.py` на тех же
функциях извлечения признаков, что использует сабмит. В ячейке применяется
Лаплас `alpha=1`; ячейки меньше 30 строк откатываются к приору категории.
Таблица обучена только на 11 024 train-строках. В её шапке есть
`fit_rows` и `split_id`; сумма `count` по ячейкам равна 11 024.
`holdout_metrics` хранится отдельно в `train/metrics.json` и не входит в shipped-артефакт.

Явное отрицание ищется в окне Evidence вокруг сработавшего маркера и не
зависит от длины карточки. В train есть откалиброванные explicit-ячейки
с размерами 182 и 55. Их эмпирический знак противоречит логическому
исключению рубрики. Поэтому для negative-only сигнатуры честно
зафиксирован рубричный cap 0.01. Смешанная positive+negative сигнатура
по-прежнему калибруется эмпирически.

Детерминированный holdout содержит 1 947 строк; train-часть — 11 024 строки;
в полном наборе найдено 1 778 групп дублирующего текста.

| метрика | значение |
| --- | ---: |
| category macro-F1 mean | **0.610075** |
| category positive-F1 mean | 0.521565 |
| global macro-F1 | 0.793964 |
| БАД macro / positive | **0.672578 / 0.851039** |
| ЛВЖ macro / positive | **0.547571 / 0.192090** |

Константный baseline из ревью: mean 0.4589; БАД macro 0.4269; ЛВЖ macro
0.4908. Пороги 0.475480 для БАД и 0.927885 для ЛВЖ подобраны на
train-части. На holdout обе категории строго бьют свою константу, а среднее
строго выше целевого гейта 0.5756.

## Блок C — каркас Фазы 1

| Пункт | Реализация и критерий |
| --- | --- |
| C1 | ошибка импорта или `load()` отключает только свою стадию и увеличивает `load_error:<name>`; fallback на `rules` разрешён только нулевой стадии; `[rules, missing]` обрабатывает все N строк ровно через `rules` |
| C2 | flush зависит от `flush_interval_sec`, обязательный финальный снапшот сохранён; N=4000/batch=8 дал не более трёх flush и `<2 s` flush time |
| C3 | `processing_start` ставится после load; init вычитается из бюджета; прогрев ограничен 15% N независимо от `batch_size`; деградации разделены минимум `N//50` товарами, восстановления — `N//5`; Public/batch=8 даёт не более 10 переходов |
| C4 | `max(180, min(2400, 0.63*N))`, плюс `ECUP_HARD_LIMIT_SEC`; соседние N не дают скачка >1.5× |
| C5 | пути сортируются; `ImageLoader.iter_batches(items,budget)` вызывается побатчево; L0→L1 реально меняет 3 изображения на 1 |
| C6 | `Budget.deadline_monotonic` фиксирует абсолютный дедлайн; частичный predictor покрывается defaults |
| C7 | summary содержит stage/prior, level, probability bins, load/predict/init, rejected sink rows и images attached |

## Блок D и поставка

- D1: удалены `discover()` и фактически мёртвая ветка registry lookup в Router.
- D2: `tools/build_submission.sh`, `tools/dry_run.sh` и `tests/` находятся в
  репозитории, но намеренно не входят в evaluator-архив: архив содержит только
  автономный payload `submission/`. Они передаются рядом с архивом и README.
- D3: процессный dry-run зелёный; Docker Desktop был запущен, но Linux engine
  не создал pipe `dockerDesktopLinuxEngine`. Поэтому cold start контейнера и
  `--network none` остаются непроверенными до появления рабочего Linux-хоста.
- D4: запятые, `;`, CR/LF и двойные кавычки удаляются из комментария до CSV.
  Поэтому стандартный CSV и наивное разбиение запятой одинаково видят поле
  result (при условии обычного id без запятой).
- E6: все 18 исходных шаблонов не содержат запятых и читаются без зависимости
  от санитайзера; сгенерированные комментарии остаются в диапазоне 50–300.

## Оставшиеся риски

1. Linux-контейнер с `--network none` и cold-start образа не проверены из-за
   недоступного Docker daemon. Это единственный незакрытый инфраструктурный gate.
2. Явные исключения имеют эмпирический знак, противоречащий рубрике. Для
   negative-only сигнатуры используется документированный cap 0.01; после
   появления новых данных это ограничение нужно перепроверить.
3. Реальные изображения проверены по central directory ZIP, не декодированы;
   bounded decode остаётся реализацией Фазы 1 за готовым контрактом.
